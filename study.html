The study: how much damage is out there?

A famous 2016 paper found gene-name errors in about 1 in 5 scientific papers with gene lists. A 2020 follow-up and a 2023 news report showed the problem had not gone away. This tool makes it cheap to measure again: run it on a pile of public files and count.

What is here today

Ready: a command-line script (npm run study) that scans a folder of files, writes one row per file and one summary, and never uploads anything.

Not done: I could not run it on real published supplementary files, because the build machine cannot reach those sites. The script that downloads files from Zenodo is included, but it has not been tested against the live site. So there is no headline number here yet, and I will not make one up.

How to run it yourself

  1. Install Node 20 or newer, then run npm install in the project folder.
  2. Put the files you want to check in a folder, for example my-files. Or try npm run study -- --fetch "gene expression" --limit 50 my-files to download public files from Zenodo.
  3. Run npm run study -- my-files.
  4. Read study-output/summary.md and study-output/files.csv.

How to read the result honestly

  • Count only very likely findings as errors. “Probably” and “worth a look” are leads, not proof.
  • A file with a flagged gene is not proof the paper’s conclusions are wrong. It shows a cell was changed.
  • Report how many files could not be read, so nobody thinks missing files meant clean files.
